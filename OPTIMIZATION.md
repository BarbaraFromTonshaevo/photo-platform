# Паспорт контекста: оптимизация главной страницы

Сводка по большой серии правок вокруг Lighthouse-аудита, оптимизации изображений/чанков, навигации по секциям и page-transition. Цель файла — чтобы следующая сессия (или вы сами через месяц) не переоткрывала уже пройденные решения и не наступала на те же грабли.

## Статус по исходному Lighthouse-аудиту

### Performance — сделано
- LCP hero-изображение: `preload` на `<NuxtImg>` в `PageHomeHero.vue`.
- Логотип хедера: заменён на `logo-icon.png` (60×60, ~5КБ вместо 340КБ), `format="webp"` + `quality`.
- Глобальный дефолт `image: { format: ['webp'], quality: 80 }` в `nuxt.config.ts` — страховка для картинок, где кто-то забудет прописать format/quality вручную.
- Лента фото жанров портфолио (`PageHomePortfolioGenre.vue`): реальные `width`/`height` каждого фото в `portfolioGenres.ts` (метаданные, как их отдаст будущий API/админка) + производный `renderWidth`/`renderHeight` (высота закапана на 1000px) считается в самом компоненте под конкретную вёрстку ленты — не путать эти две вещи, они разного назначения (см. ниже).
- Разделение GSAP/ScrollTrigger из глобального Lenis-плагина в opt-in composable — страницы без scroll-анимаций больше не тянут GSAP+ScrollTrigger в бандл. Подробности — отдельный раздел ниже, там много нюансов.
- `@fancyapps/ui` — уже был удалён из зависимостей ещё до этой серии правок.

### Performance — НЕ сделано, следующий шаг
- **Ленивая гидратация** below-the-fold виджетов в `PageHome.vue` (`LazyPageHomeAbout/Portfolio/History/Album/Contacts`) — сейчас только `Lazy*` код-сплит, без `hydrate-on-visible`/`hydrate-on-idle`. Это следующий по плану пункт, см. раздел "Дальнейший план" ниже — там же обоснование, почему именно в таком порядке.
- Решить, что делать с `@nuxtjs/i18n` — модуль подключен для двух локалей, но реально `$t()`/`useI18n()` используется только в хедере/меню (~6 мест), весь контент секций захардкожен на русском. Либо доперевести, либо убрать модуль.

### SEO — не тронуто вообще
- Нет `useSeoMeta`/`useHead` на уровне страниц — только один глобальный `title`/`description` в `nuxt.config.ts`.
- Нет Open Graph / Twitter Card тегов, нет canonical URL.
- `hreflang`/`baseUrl` для `@nuxtjs/i18n` не настроены.
- `public/site.webmanifest` — `name`/`short_name` всё ещё пустые строки.
- Нет `sitemap.xml`.

## Навигация по секциям + page-transition

Полностью реализовано и работает в связке. Ключевые файлы:

- **`app/01.shared/lib/useScrollToSection.ts`** — доскроллить к элементу по `id` через Lenis. Перед измерением `offsetTop` ждёт стабилизации позиции (`waitForStablePosition`, до 30 кадров rAF-поллинга) — нужно, потому что Lazy-виджеты выше цели могут ещё не дорендерить реальный контент, а высота ещё не финальна. Принимает `isImmediate` — прыжок без анимации (для case'ов, когда сам скролл должен быть скрыт от пользователя) или плавный (для клика, уже находясь на `/`).
- **`app/01.shared/lib/usePendingScroll.ts`** — общий на всё приложение `ref<{type:'section',id} | {type:'top',value}>`. Единственный канал, через который "что скроллить после перехода" передаётся из клика в хедере в `onEnter` page-transition'а.
- **`app/01.shared/lib/usePageFadeTransition.ts`** — `onEnter`/`onLeave` для `<Transition css="false">` через **нативный Web Animations API** (`el.animate(...)`), не GSAP — сознательно, чтобы не тащить GSAP в `app.vue`, который грузится на каждой странице. `onEnter`: элемент сразу ставится `opacity: 0`, читает и обнуляет `pendingScroll`, выполняет соответствующий скролл (`immediate: true`, страница ещё невидима), и только потом проигрывает fade-in.
- **`app/app.vue`** — `<NuxtPage :transition="pageTransition" />`, `mode: 'out-in'`.
- **`app/router.options.ts`** — `scrollBehavior` **никогда сам не скроллит** (`return false` всегда). Только **записывает** намерение в `pendingScroll` (если оно ещё не выставлено кликом в хедере) — сам физический скролл всегда происходит позже, внутри `onEnter`. Это принципиально: если дать `scrollBehavior` скроллить самому, это происходит, пока старая страница ещё видима и только начинает fade-out — вызывает видимый "прыжок" контента перед его исчезновением.
- **`app/04.widgets/header/ui/HeaderBase.vue` / `HeaderMenu.vue`** — `onNavClick`: проверка модификаторов (Ctrl/Cmd/средняя кнопка мыши) и `event.preventDefault()` — **строго до** любого `await`, иначе `NuxtLink`/браузер успевают выполнить нативную навигацию параллельно с нашей. Кросс-страничный клик → `pendingScroll.value = {type:'section', id}` → `navigateTo('/')`. Клик уже на `/` → напрямую `useScrollToSection(id)`.
- **`app/04.widgets/page-home/ui/PageHome.vue`** — id-якоря (`about`/`portfolio`/`story`/`contacts`) — явные обёрточные `<div id="...">` вокруг каждого `Lazy*`-виджета, **не** через Vue attrs-fallthrough. Важно для `Portfolio` конкретно: он использует GSAP `pin: true`, который оборачивает пиннящийся элемент в служебный pin-spacer — если `id` попадает через fallthrough прямо на пиннящийся корень, `offsetTop` после того как ScrollTrigger отработал становится ненадёжным (второй-третий клик промахивается мимо позиции).
- **`app/01.shared/lib/useHeaderZoneObserver.ts`** — `onUnmounted` теперь тоже вызывает `onLeave()`. Раньше при уходе на другую страницу секция (Hero/Portfolio), форсирующая тёмную тему хедера, размонтировалась не успев "выехать" из зоны IntersectionObserver — `forcedHeaderTheme` навсегда оставался залипшим на прошлом значении.

## Lenis / GSAP: архитектура синхронизации (самая тонкая часть)

- **`app/plugins/lenis.client.ts`** — клиентский плагин, создаёт `Lenis({ autoRaf: false })` и **свой собственный** `requestAnimationFrame`-цикл (не рекурсия — каждый вызов возвращает управление браузеру до следующего кадра, планирует свой же следующий вызов через `rafId`). Даёт наружу `lenisStopDefaultRaf` через `provide`.
- **`app/01.shared/lib/useLenis.ts`** — единственный фасад для всего, что связано с Lenis: `useLenis()` (сам инстанс), `useLenisStopDefaultRaf()`. Нигде в проекте не должно быть прямого `useNuxtApp().$lenis`/`$lenisStopDefaultRaf` — только через этот файл.
- **`app/01.shared/lib/useGsapScrollSync.ts`** — opt-in composable, вызывается из `PageHomePortfolio.vue`, `PageHomeAbout.vue`, `PageHomeAlbum.vue`, `PageHomeContacts.vue` (у всех есть ScrollTrigger-твины). Внутри `onMounted` (критично — SSR не имеет `$lenis`, вызов вне `onMounted` крашит сервер), защищён модульным флагом `synced`, чтобы реальная настройка (остановка дефолтного raf, `lenis.on('scroll', ScrollTrigger.update)`, `gsap.ticker.add(...)`) произошла ровно один раз, сколько бы виджетов её ни звали. `gsap.registerPlugin(ScrollTrigger)` — на уровне модуля (гарантированно один раз, за счёт кеширования ES-модулей).
- **Важно про бандлы:** после того как `gsap`+`ScrollTrigger` один раз загрузились (например, при заходе на `/`), они остаются в памяти вкладки на всю сессию — уход на страницу без ScrollTrigger не "выгружает" их и не переключает Lenis обратно на дефолтный цикл. Это осознанно и нормально: цель была не тратить трафик на **скачивание** GSAP тем, кто его вообще не встретит, а не экономить рантайм на уже загруженной странице.
- **История багов, которые тут ловили** (на случай дежавю): двойной тик Lenis (`autoRaf: true` в конструкторе + свой ручной цикл одновременно — оставьте `autoRaf: false`!), `preventDefault` после `await` не срабатывает, гонка между `scrollBehavior` и fade-transition.

## Портфолио: пайплайн фото жанров

- **`app/04.widgets/page-home/config/portfolioGenres.ts`** — `GenrePhoto.width`/`.height` — это **реальные** пиксельные размеры файла (2000×1333, 2000×3000 и т.п.), ровно то, что вернёт будущий API/админка при загрузке фото. Не путать с размером отображения.
- **`app/04.widgets/page-home/ui/PageHomePortfolioGenre.vue`** — `withRenderSize()` считает **производный** таргет под конкретную вёрстку ленты (высота капается на 1000px, ширина — пропорционально реальному аспекту). Это специально в компоненте, а не в конфиге — презентационное решение, а не свойство контента. Когда появится реальный API, компонент не потребует изменений.
- Бывший `waitForImages()` — **удалён**. Раньше он был нужен, чтобы узнать реальные пропорции фото до их загрузки; после появления `width`/`height` на `<NuxtImg>` браузер знает aspect-ratio сразу из атрибутов, ожидание стало не просто лишним, а вредным — конфликтовало с `loading="lazy"` на широкой ленте (фото за пределами зоны активации lazy-loading никогда не грузились → `Promise.all` вис навсегда → лента вообще не крутилась).
- Текст жанра (`animateIn`/`resetInfo`) теперь появляется **один раз**, когда жанр одновременно активен и реально в вьюпорте (`tryReveal()`, флаг `hasRevealed`), и больше не прячется обратно при повторном скролле мимо.

## Уроки, которые стоит помнить (не гуглить заново)

- `<meta viewport>` — Nuxt добавляет сам по умолчанию (дефолты `@nuxt/schema`), даже если не объявлен в `nuxt.config.ts`. Не флагать как проблему без проверки собранного `<head>`.
- `quality` на `NuxtImg` — sharp/IPX и так по умолчанию переэнкодит примерно в районе 80 для webp/jpeg, даже без явного значения. Реальный пробел — отсутствие `format`/`width`/`height`, не `quality`.
- Vue attrs-fallthrough (`id="..."` на `Lazy*`-компоненте) молча ломается для любого элемента, который сторонняя библиотека (GSAP pin) репозиционирует/оборачивает — якоря секций всегда через явный wrapper-div, не через fallthrough, если у виджета есть что-то layout-manipulating внутри.
- `event.preventDefault()` работает только если вызван **синхронно**, до первого `await` в обработчике.
- Composable, вызывающий `onMounted()` внутри себя, можно звать с верхнего уровня `<script setup>` любого потребителя (не обязательно оборачивать в его собственный `onMounted`) — главное, чтобы сам composable был вызван синхронно во время `setup()`.
- `requestAnimationFrame`-циклы вида `function loop(t){...; requestAnimationFrame(loop)}` — это не рекурсия в опасном смысле: каждый вызов завершается и стек очищается до следующего запланированного вызова.
- `loading="lazy"` на изображениях внутри JS-управляемой (не пользовательским скроллом) горизонтальной ленты может создать дедлок: картинки за пределами зоны активации never грузятся, если что-то ждёт их полной загрузки через `Promise.all`.
